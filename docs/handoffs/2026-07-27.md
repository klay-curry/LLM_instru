## 可信结果

### 已确认

- 当前赛题平台基线仍是 Qwen + Grounding DINO 保守 hybrid：`0.45`。
- VLM 直接生成坐标 `0.43`，不作为主路线；Qwen semantic tokens + 专门定位头仍是主路线。
- 8 样本 smoke test通过 forward、backward、optimizer step 和 checkpoint 重载，重载预测最大差为 0。
- 32 样本同集过拟合：
  - semantic：`ACC@0.5=0.5938`，mean IoU `0.5680`；
  - null semantic：`0.3125`，mean IoU `0.3899`。
- 独立 RefCOCO validation pilot：
  - semantic：`ACC@0.5=0.1013`，mean IoU `0.2429`；
  - null semantic：`0.0947`，mean IoU `0.2360`。
- semantic 在独立 validation 上方向一致地更好，但只提升 `+0.0066 ACC`，目前只是初步正向信号。

### Batch 探测

| Batch | Samples/s | Peak allocated | Peak reserved |
|---:|---:|---:|---:|
| 64 | 1832.9 | 1.12GB | 1.56GB |
| 128 | 1785.3 | 1.86GB | 2.72GB |
| 256 | 1811.8 | 3.34GB | 5.00GB |
| 512 | 1848.5 | 6.31GB | 9.50GB |

结论：四档 GPU 计算吞吐接近。batch 512 没有显著速度优势，并使 3,581 条 pilot 数据每 epoch 只有 7 次更新。下一正式训练优先测试 batch 128 或 256，并按 optimizer updates、validation 指标和 wall-clock time 决策，不按显存占用决策。

## 已知限制

1. `refcoco_train.pt` 是约 8.2GB 单体 PyTorch pickle，不能高效随机访问；加载时间依赖系统 page cache。
2. 旧预计算脚本可能将一个 reference 的 captions 数组整体转换成字符串传给 Qwen，而不是规范单条 Query。
3. 当前训练每个 epoch 都重新读取、解码 COCO 图片并运行 frozen DINOv2，重复开销没有缓存。
4. Exp-008 只用 train cache 前 3,581 条，存在排序偏差；3 epochs、batch 512 仅 21 次 optimizer update。
5. 当前只验证 RGB 空间定位和 Qwen 语义条件，没有训练 Depth/IR 空间分支。
6. RefCOCO validation 改善不能直接解释为官方赛题提升，必须最终通过平台分数验证。
